MathVerse 审计：DeepTutor 功能利用度 & 多用户高并发

本报告在 regenerate / web_search 两点上修正旧文档 mathverse-deeptutor-utilization-review-20260603.html（二者已在 commit 2f51d3e 修复）。

0. 总评

充分DeepTutor 功能利用覆盖 ~75% 有价值表面（24 router）；未用的多为有意弃用或外部条件卡住。
合格多用户隔离（正确性）真隔离：mv_{uid}_ 命名 + DtResource 归属表；唯一例外是只读全局 memory。
能力具备，尚未支持高并发（规模）横向扩展套件齐全，但生产仍单机单 worker、零真机验证。扛 5000 日活够，称不上万级高并发。
一句话：功能用得充分、多用户是真隔离；但"高并发"目前是"代码就绪却全部休眠且零真机验证"——具备能力，尚未支持。而这一切的前提是 PR #15 + 高并发补丁全是 static-verified only，这是全局 #1 残留风险。

2. 多用户隔离 — 真隔离

机制说明出处
命名隔离MathVerse 自取名的资源（KB/session）一律 mv_{uid}_ 前缀deeptutor/tenancy.py · scope()
归属表服务端分配 id 的资源（notebook/book）用 DtResource 表做 user_id ↔ (domain, dt_id) 映射防越权dt_ownership.py · models DtResource
唯一例外DeepTutor long-term memory 是单一全局工作台（固定枚举 key，无 per-user 维度），无法按命名隔离 → 仅只读巡查 + 默认关闭config deeptutor_memory_enabled=False

结论：多用户正确性层面合格。memory 的全局性是引擎设计所限，MathVerse 用「只读 + 默认关」把风险降到最低，取舍正确。

3. 高并发 — 能力具备，尚未支持

两个并发面（不可混为一谈）

  • 面 A unified_ws turn 运行时 → /ws/tutor 用它，有进程本地状态。
  • 面 B chat/vision/judge → MathVerse 主路径（解题）用它 deeptutor_ws.py，相对无状态。
