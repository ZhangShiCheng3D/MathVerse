为什么是 Capacitor 包 H5：现有 Taro 工程已配 build:h5 目标，样式几乎全是内联 style（高度可移植），复用 100% 现有 UI 与业务逻辑，5+ 个页面立即可用。代价是 WebView 底（非原生控件）——对这类"读题/讲解/列表"内容型应用足够。其余三条路线（Taro-RN / 原生 Kotlin / Expo）都要重写 UI 或大量适配，违背"最少代码解决问题"。

0 · 整体架构

┌─────────────────── Android APK (Capacitor) ───────────────────┐ │ WebView (androidScheme: https://localhost) │ │ └─ Taro build:h5 产物 (dist/) ── 现有 5+ 页面，零改 │ │ └─ Taro.request ──┐ │ │ │ CapacitorHttp 插件拦截 │ │ ▼ 改走【原生 HTTP】→ 绕过浏览器 CORS │ └──────────────────────────┼────────────────────────────────────┘ │ https://kuangyebar.cn ▼ mathverse-api (FastAPI) ├─ 现有 /api/solve /learn /me /pay …（不变） └─ 新增 /api/auth/sms/send · /verify（手机登录） │ ▼ SMS 服务商（腾讯云/阿里云，凭证待配） 未配 → dev 模式：验证码直接回传，现在即可测
CORS 决策：Capacitor 启用内置 CapacitorHttp 插件后，WebView 里的 fetch/XHR（即 Taro.request 在 h5 的底层）被改写为原生 HTTP 请求，不经过浏览器同源策略 → 后端 CORS 配置零改动。比往生产 .env 的 cors_origins 加 https://localhost 白名单更干净、更不易踩坑。

1 · 后端：手机号短信登录

零改表：User 模型已有 phone 字段（phone = Column(String, nullable=True)）。OTP 用新表 SmsCode，init_db 启动时 create_all 自动建（只建缺失表，不动现有数据，部署安全）。

1.1 新增 ORM 模型 models/all.py

class SmsCode(Base):
    __tablename__ = "sms_codes"
    id = Column(String, primary_key=True, default=_new_id)
    phone = Column(String, nullable=False, index=True)
    code = Column(String, nullable=False)          # 6 位数字
    expires_at = Column(DateTime, nullable=False)  # now + 5 min
    consumed = Column(Boolean, default=False)
    created_at = Column(DateTime, default=_now)

1.2 服务 services/sms.py

  • generate_and_store(db, phone) -> code：生成 6 位码，写 SmsCode，调 _provider_send(phone, code)。
  • verify(db, phone, code) -> bool：取该手机未消费、未过期的最新码比对；成功标记 consumed=True。
  • _provider_send：sms_enabled=True → _send_tencent（腾讯云短信 SDK，已实现，懒加载，凭证从 env）；否则 no-op + 日志（dev 模式）。发送失败抛 RuntimeError → 路由返回 502。

1.3 配置 config.py

sms_enabled: bool = False          # 未启用 → dev 模式（验证码回传，便于测试）
sms_provider: str = "tencent"      # tencent | aliyun
tencent_sms_secret_id: str = ""
tencent_sms_secret_key: str = ""
tencent_sms_sdk_app_id: str = ""
tencent_sms_sign: str = ""
tencent_sms_template_id: str = ""  # 模板取单参 {1} = 验证码
tencent_sms_region: str = "ap-guangzhou"
sms_code_ttl_seconds: int = 300    # 5 分钟
sms_resend_interval: int = 60      # 同号 60s 限发一次

1.4 路由 routes/auth.py

端点请求 / 行为返回
POST /api/auth/sms/send{phone}。校验号码格式 ^1[3-9]\d{9}$；60s 限频（查最近一条码的 created_at）；生成+存+发。dev: {sent:true, debug_code:"123456"}；生产: {sent:true}
POST /api/auth/sms/verify{phone, code}。校验码；按 phone find-or-create User（新用户 nickname=「用户+尾号」）；发 JWT。{access_token, refresh_token, user:{…}}（结构同 mp-login）
dev 模式回传验证码仅在 sms_enabled=False 时返回 debug_code，方便现在就把登录流跑通并写测试。配齐短信商凭证（sms_enabled=True）后自动停止回传——与"微信密钥延后"完全同构。

1.5 测试 tests/test_auth.py

  • 非法号码 → 422/400；send 返回 debug_code（dev）。
  • verify 正确码 → 200 + 三字段 + 新建 User（同号二次 verify 复用同一 User）。
  • 错码 / 过期 / 已消费 → 400。
  • 60s 内重复 send → 429。

3 · Capacitor 安卓壳

3.1 依赖与配置

npm i -D @capacitor/cli
npm i @capacitor/core @capacitor/android
npx cap init "数界 MathVerse" cn.kuangyebar.mathverse --web-dir dist

capacitor.config.ts 关键项：

{
  appId: 'cn.kuangyebar.mathverse',
  appName: '数界 MathVerse',
  webDir: 'dist',
  server: { androidScheme: 'https' },
  plugins: { CapacitorHttp: { enabled: true } }   // ← 绕过 CORS 的关键
}

3.2 出包流程

# 1. 构建 H5 产物（API 指向生产）
TARO_APP_API_URL=https://kuangyebar.cn npm run build:h5
# 2. 生成/同步原生工程
npx cap add android         # 首次，生成 android/
npx cap sync android        # 之后每次：把 dist/ 同步进原生工程
# 3. 出 APK（本机已有 SDK+JDK）
cd android && ./gradlew assembleDebug
# 产物：android/app/build/outputs/apk/debug/app-debug.apk

新增 npm 脚本："app:sync": "npm run build:h5 && npx cap sync android"。

首次 Gradle 构建风险：会联网下载 Gradle 发行版 + Android 依赖，量大且本机代理（198.18.x）历史上偶有超时。若失败，按 runbook 用国内镜像或离线 Gradle 重试——这是环境问题，不是代码问题，不阻塞代码交付。
