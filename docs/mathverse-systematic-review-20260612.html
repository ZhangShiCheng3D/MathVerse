2. P1 — 已修复

P1-1 /ws/solve 完全绕过 cost-guard 与 solve 观测计数 已修

位置：app/routes/solve_ws.py。POST /deep·/quick·/vision·/visualize 与 /ws/tutor 都套了 cost_guard.enforce_cost_budget + 消耗记账，唯独流式 solve WS 两者皆无。而前端优先走 WS、POST 仅作回退——这是 deep-solve 的主路径：一旦运营启用 DAILY_TOKEN_BUDGET_HARD，免费/匿名用户走 WS 即可绕过限流，且主路径消耗不计入预算、不进 /api/metrics 的 solve 计数。PR #15 第 5-7 commit 修了 /ws/tutor 的同类缺口但漏了这里。

修法：取得 user 后按与 POST 相同顺序（budget → quota）调用 cost_guard.enforce_cost_budget（超限 → {"type":"error","code":503}）；结果发送前调用 _record_solve("deep", degraded, question, answer)。回归测试 test_solve_stream_cost_guard_sheds_free。

P1-2 匿名 tutor 前后端契约错位 — 「重答」吞答案 + 假连续对话 已修

位置：后端 app/routes/tutor.py（done 事件）；前端 src/stores/tutor.ts + src/pages/tutor/index.tsx。06-07 把 continuity/regenerate 改为仅限登录（正确），但 done 仍向匿名返回 session_id：前端存下并在下条消息回传，后端忽略 → UI 显示连续对话但引擎每条都是新会话（无上文）。且「重答」按钮不看 session：匿名点击时 store 先弹掉最后一条 assistant 气泡再被后端拒绝 → 答案丢失 + 报错。

修法（三处）：① 后端 done 仅对登录用户返回 session_id，匿名为 null；② 前端 canRegen 增加 !!sessionId（匿名永远拿不到 id → 按钮不出现）；③ 气泡移除从「点击即弹」改为延迟到新一轮真正产出内容时（pendingRegenPop 在首个 stream/result 事件时生效，error/连接失败/空产出时复位）——重连失败不再丢答案。回归断言加在 test_tutor_anon_session_not_owned（done.session_id is None）。

P1-3 get_current_user 不校验 token type — refresh token 可当 access token 用 已修

位置：app/middleware/auth_middleware.py（存量问题，非 06-07 引入）。两个 WS 入口的 _user_from_token 都检查 type == "access"，HTTP 路径没有 → 7 天有效期的 refresh token 可直接作为 Bearer 调所有受保护 HTTP 端点，15 分钟 access 短时效与 /refresh 轮换点被架空。

修法：get_current_user 解码后校验 payload["type"] == "access"，否则 401（get_optional_user 经由它自动继承）。回归测试 test_protected_endpoint_rejects_refresh_token。

3. P2 — 已修复

#问题修法
P2-1dt_ownership.record 的 check-then-insert 非原子：并发双插时第二个 commit 抛未捕获 IntegrityError 且不 rollback，同请求后续 DB 写（archive/log_event）连带失败commit 包 try/except IntegrityError: rollback()（等效 INSERT OR IGNORE）。部署注意 生产已有的 dt_resources 表不会自动获得新加的 UniqueConstraint（本项目无 migrations，create_all 不改已有表）——有该 catch 后无约束也安全（竞态最坏结果是冗余行，ownership 语义不受影响）；如需约束生效需重建表
P2-2tutor 匿名 + use_rag + 自定义 kb_name 时产出不存在的 mv_anon_* 库名（kb 路由全部要求登录），RAG 落空；与 solve/solve_ws/learn 的防护不一致与其余三处对齐：req_kb and uid 才用用户库，否则回退 mv_curriculum_{stage}
P2-3/api/learn/lecture 与 /exercise/generate 是 optional-auth 的 LLM 消耗端点，但无 content-filter、无 cost-guard、消耗不记账补 filter_text(kp_name)（400）+ enforce_cost_budget + 成功后 cost_guard.record。quota 故意未加——讲解/练习是否计入解题额度是产品决策（学习页可能是免费漏斗），保持现状待定夺
P2-4/ws/tutor 对 result 与引擎原生 ask_user/error 走 send_json(ev) 原样转发，带出 metadata/turn_id 等内部字段，error 可能含原始异常文本统一翻译为 {"type", "content"}（前端本就只读这两个字段，零成本收紧）
