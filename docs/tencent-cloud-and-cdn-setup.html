1. CAM 密钥使用原则

  • 一对 SecretId/SecretKey 可调全部产品 API（COS、SMS、CAM…），新项目不需要新密钥，直接复用。
  • 查询账号 APPID（建 COS bucket 必须用）：CAM API GetUserAppId，npm 包 tencentcloud-sdk-nodejs-cam。
  • 建议（未做，可选）：为每个项目建 CAM 子账号、只授该项目用到的产品权限，泄漏时影响面更小。

2. ECS + nginx「一台机多项目」路径反代模式

一台 ECS、一个域名、一张 SSL 证书，按 URL 路径前缀 挂载多个项目——新项目零成本上线，不用买新域名/证书。

用户 ──https──> host nginx (server_name kuangyebar.cn, 持 SSL) ├── /yk/ → 127.0.0.1:3000 (砚卡 API+后台) ├── /xx/ → 127.0.0.1:3001 (其他项目 …) └── / → 默认站 每个项目自己跑 Docker Compose，端口只绑 127.0.0.1，不暴露公网。

nginx 配置要点

location /yk/ {
    proxy_pass http://127.0.0.1:3000/;   # 注意尾部 / —— 去掉 /yk 前缀转发
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 300m;           # 大文件上传必调，默认 1m
}
ECS 带宽是最贵的瓶颈。小水管（几 Mbps）下大文件绝不要流经 ECS——上传走 COS 直传（§4），下载/媒体走 CDN（§3）。带宽计费方向：出向按购买带宽限速，入向 ≤10Mbps 套餐时也被限 10Mbps。
Express 在 nginx 后面记得 app.set('trust proxy', 1)，否则限流按 nginx 的 IP 聚合、X-Forwarded-For 告警。

3. EdgeOne CDN（静态/媒体加速）

用途：媒体文件（图片/音频）从边缘节点出流量，不占 ECS 带宽。砚卡用它扛 Anki 牌组媒体。

接入步骤

  1. EdgeOne 控制台添加站点 → 加速域名用 子域名（如 www.kuangyebar.cn），DNS 把它 CNAME 到 EdgeOne 给的边缘地址。
  2. 源站设 ECS IP（129.211.224.227）。
  3. 回源 HOST 改写为主域名（kuangyebar.cn）——见下面坑 #1，最容易翻车的一步。
  4. 缓存规则：按路径匹配（如 /yk/api/media/*），遵循源站 Cache-Control（源站对媒体发长缓存 + immutable）。
  5. 应用侧把媒体基址指到 CDN 域名（砚卡：env PUBLIC_MEDIA_BASE=https://www.kuangyebar.cn/yk/api/media）。

EdgeOne 踩坑清单

#1 回源 HOST 不改写 → 302 跳登录页。host nginx 的 vhost 只认 server_name kuangyebar.cn（无 www）。CDN 带着 www. 回源会落到默认站。必须在 EdgeOne 配「回源 Host 改写」为主域名。
#2 绝不能直连 .eo.dnse0.com CNAME 目标。其证书是 *.cdn.myqcloud.com，SAN 不匹配你的域名，TLS 直接握手失败。一律走自己的加速域名。
#3 本机验证不可信。开发机的代理软件会把边缘域名劫持成 198.18.x.x fake IP。验证 CDN 必须登 ECS 从服务器侧 curl（必要时 --resolve www.域名:443:<边缘IP>）。

4. COS 对象存储 —— 大文件直传架构

用途：用户上传大文件（百 MB 级 PDF）绕过 ECS 小带宽；第三方服务（OCR 等）也直接从 COS 拉文件。ECS 公网全程不过文件字节。

App ──预签名 PUT 直传──> COS bucket（公网大带宽，上传流量免费） App ──objectKey（几百字节 JSON）──> ECS API worker ──同地域内网拉取（免费、百兆+）──> COS 第三方(OCR等) <──预签名 GET URL，自己拉，COS 出流量 ¥0.5/GB──┘

建 bucket（纯 API，控制台都不用开）

// npm i cos-nodejs-sdk-v5
const COS = require('cos-nodejs-sdk-v5');
const cos = new COS({ SecretId, SecretKey });
// bucket 名必须带 APPID 后缀
await cos.putBucket({ Bucket: 'myproj-uploads-1258541757', Region: 'ap-guangzhou' });
// 生命周期：上传目录 7 天自动删，永不堆积
await cos.putBucketLifecycle({ Bucket, Region, LifecycleConfiguration: { Rules: [{
  ID: 'expire-uploads-7d', Status: 'Enabled',
  Filter: { Prefix: 'uploads/' }, Expiration: { Days: 7 } }] } });

预签名 URL（服务端几毫秒，无流量）

// PUT（给客户端直传，15 分钟）/ GET（给第三方拉取，2 小时）
cos.getObjectUrl({ Bucket, Region, Key, Method: 'PUT', Sign: true, Expires: 900 }, cb);
cos.getObjectUrl({ Bucket, Region, Key, Method: 'GET', Sign: true, Expires: 7200 }, cb);

关键事实

项事实
同地域内网ECS↔COS（同为 ap-guangzhou）走内网，免费且不占公网带宽，SDK 自动走内网 DNS
费用存储 ¥0.099/GB/月 · 外网下行 ¥0.5/GB · 上传免费 · 请求 ¥0.01/万次
客户端直传预签名 PUT 不需要任何 SDK，标准 HTTP PUT 即可（RN 用 FileSystem.uploadAsync BINARY_CONTENT）
地域必须和 ECS 同地域（广州 ap-guangzhou）才有内网；建 bucket 时定，不可改
安全bucket 私有读写；密钥只在服务端；客户端拿到的预签名 URL 限时限单个对象
隐藏技巧（实测，官方未文档化）：百度 PaddleOCR AI Studio 任务接口 POST /api/v2/ocr/jobs 支持 JSON 体 {"model":"...","fileUrl":"<COS预签名GET URL>"} 提交，它自己去拉文件——multipart 里塞 fileUrl 字段会报「空文件」，必须 JSON。其他第三方服务接 COS 时优先找有没有 URL 提交模式。

5. 腾讯云短信（验证码）

开通流程

  1. 短信控制台 → 应用管理 → 创建应用（秒建免审）→ 得 SdkAppId。
  2. 签名管理 → 申请签名（需资质：营业执照 / 小程序主体 / App 用户协议截图，审核 1-2 小时～1 天）。签名内容必须与控制台一字不差。
  3. 模板管理 → 申请正文模板。记录模板有几个参数——发送时 TemplateParamSet 数组长度必须严格一致，多一个少一个都拒发。

找不到签名/模板信息时：用 API 直接查（实测可用）

// npm i tencentcloud-sdk-nodejs-sms —— 控制台翻不到就让代码自己说
const c = new (require('tencentcloud-sdk-nodejs-sms').sms.v20210111.Client)({
  credential: { secretId, secretKey }, region: 'ap-guangzhou' });
await c.DescribeSmsTemplateList({ International: 0, Limit: 50, Offset: 0 }); // 全部模板+状态+原文
await c.DescribeSmsSignList({ International: 0, Limit: 50, Offset: 0 });     // 全部签名+状态

发送（Node）

await client.SendSms({
  PhoneNumberSet: ['+86' + phone],
  SmsSdkAppId: '1401139844',
  SignName: '南京淳纯科技有限公司',     // 与控制台完全一致
  TemplateId: '2658508',
  TemplateParamSet: [code],            // ← 个数 = 模板 {n} 个数，砚卡模板是单参数
});
// 返回 SendStatusSet[0].Code !== 'Ok' 视为失败（额度不足/签名模板不匹配都在这暴露）

服务端防滥用三件套（砚卡现成实现可抄）

  • 重发冷却 60s/号 + 每号每天 10 条 + 验证码 5 分钟过期（Redis 存储，server/src/services/codeStore.ts）
  • auth 路由独立限流（5min/10 次/IP）
  • 生产随机 6 位码；本地未配密钥时固定 123456 走日志，开发不耗短信
短信按条扣账号余额（国内约 ¥0.045/条，新账号可能需先购最小套餐包）。余额耗尽 = 全体用户无法登录，务必设余额告警（§6）。

7. 通用踩坑清单（跨项目都会遇到）

#1 compose 显式 env 透传：docker-compose 用 environment: 列举变量时，.env 新增的变量不会自动进容器，必须在 compose 里补 VAR: ${VAR:-}。且 compose 里的默认值（如 ${X:-120}）会盖掉代码内默认值——代码改默认后要同步 compose。
#2 127.0.0.1 vs localhost：开发机代理常监听 127.0.0.1:7890 并劫持 127.0.0.1 流量返回 502，本地服务一律用 localhost 连。
#3 Windows 终端发中文 JSON 会变 GBK 乱码：git-bash/PowerShell 里 curl 提交中文 body，服务端收到乱码——测试中文参数用文件（-d @body.json，文件存 UTF-8）或让真实客户端发。
#4 GitHub 单文件 100MB 硬限：教材 PDF/apkg 这类大素材入库必须 Git LFS（免费档 1GB 存储 + 1GB/月下载带宽）。
#5 验证 CDN/边缘域名必须从 ECS 侧：本机代理会把域名劫持成 198.18.x fake IP，本机 curl 结果不可信。

8. 新项目接入 Checklist

  1. ☐ 复用 CAM 密钥（或为新项目建子账号）
  2. ☐ ECS：新项目 Docker Compose 绑 127.0.0.1 新端口 → host nginx 加 location /newproj/ 反代（带尾 / 去前缀）→ 复用现有 SSL
  3. ☐ 大文件上传？→ 同地域建 COS bucket（API 三行代码，§4）+ 生命周期规则 + 预签名直传
  4. ☐ 媒体/静态量大？→ EdgeOne 加缓存规则（注意回源 Host 改写）
  5. ☐ 要短信？→ 同应用复用 SdkAppId + 申请新模板即可（签名通用）
  6. ☐ Express 设 trust proxy；nginx 调 client_max_body_size
  7. ☐ 费用中心确认余额告警覆盖新增消耗
