核心判断：这套架构 不需要 GPU

真正的 LLM 推理在外部 API（DeepSeek deepseek-chat 文本 + DashScope text-embedding-v3 / qwen-vl-max 视觉），本机三个容器（mathverse-api / deeptutor / qdrant）只做编排、长连接转发与向量检索。负载是 I/O 密集（等外部 API），不是算力密集。因此 5000 日活的瓶颈是「并发连接 + 内存 + 单机写库 + 外部 API 花费」，单机 async 事件循环足以承载，无需立刻上 GPU 或多副本。

1. 推荐服务器规格

8 vCPU突发峰值 + 多核余量
16 GBqdrant + deeptutor 并发 + 留 PG 余地
100 GB SSDSQLite/qdrant/RAG 索引/日志/备份
按量带宽 ≥5 Mbps晚高峰潮汐，避免固定带宽限速
负载维度5000 日活估算
日请求量5000 × ~20 次/人 ≈ 10 万次/天
峰值 QPS集中晚间 4–6 小时 → 均值 ~7，突发 ~20–30
峰值在途长连接QPS × 单次 10–30s ≈ 100–400 个并发 WebSocket
出向带宽峰值~2–3 Mbps（拍照上传是入向，通常免费）

腾讯云对标：标准型 S5.2XLARGE16（8C16G）。省钱下限 4C8G 也能扛平滑流量，但晚高峰长连接 + qdrant 增长后余量很薄，不建议更低。真正的线性成本在外部 LLM API 调用费，随用量增长，需单独做预算监控（见第 5 节成本护栏）。

2. 本次加固内容（已落地 + 测试）

项改动风险
可观测性新增 GET /api/metrics：admission 在途/容量/饱和次数、circuit 状态、外部调用错误率、各类 solve 计数与降级率、DB 写延迟、成本护栏状态无行为变更
SQLite 写吞吐synchronous=NORMAL（WAL 安全，写吞吐数倍）+ wal_autocheckpoint=1000 + cache_size≈16MB + busy_timeout 5s→10s；新增 DB 写延迟监听 + 在线备份脚本无行为变更

3. 启用与调优（运维）

所有新旗标已在 docker-compose.yml 的 mathverse-api 服务暴露，默认值保持现行为。在服务器 ~/MathVerse/.env 设置即可：

# Admission：引擎有余量可调高，引擎开始超时则调低
DEEPTUTOR_MAX_CONCURRENCY=128

# 成本护栏：估算 token/日。0=关闭。
# 推荐档位 ≈ DAU × solves/人/日 × ~3000 token/题 × 1.5 安全系数
# 5000 × 20 × 3000 × 1.5 ≈ 450M
DAILY_TOKEN_BUDGET_HARD=450000000
DAILY_TOKEN_BUDGET_SOFT=315000000   # ≈ 0.7 × hard

重新部署：cd ~/MathVerse && git pull && docker compose up -d --build --no-deps mathverse-api（--no-deps 只重建 API，不动 deeptutor/qdrant）。

在线备份（cron）

# 每天 03:00 在线热备 SQLite，保留 14 天
0 3 * * *  docker exec mathverse-mathverse-api-1 bash /app/scripts/backup_db.sh

监控接入

/api/metrics 返回 JSON，可被腾讯云监控/Prometheus exporter 抓取。建议告警线：circuit.open=true、admission.saturation_total 持续增长、solve.degrade_rate > 0.1、db_write.max_ms 飙升、cost_guard.soft_exceeded=true。该端点暴露流量规模，建议在 nginx 用 allow/deny 限制来源 IP。

4. 成本护栏触发逻辑

策略 = 软告警 + 硬熔断仅挡免费。关键事实：降级路径走的也是付费的 DeepSeek，所以「降级」并不省钱——超预算时有意义的动作只有「告警」或「挡新请求」。

  • 软阈值：仅在 /api/metrics 标红 + 计数，不挡任何人。
  • 硬阈值：免费 / 匿名用户的新 solve 请求返回 503 友好提示；付费用户永不被挡（保护付费体验 + 账单封顶）。
  • UTC 零点自动归零；进程内计数（每 worker 独立，单机单 worker 即全局）。

范围说明：护栏接在量最大的 /deep /quick /vision /visualize 四个 optional-auth 端点；/step-explain /similar 为 auth-gated 的会话内低频调用，未挡（避免打断已登录用户的连续会话）。

5. 明确推迟（不为 5000 日活上）

不启用 DeepTutor PG/Redis 多 worker 横向扩展（PR #2 的 P0–P3）。原因：

  • 5000 日活 I/O 密集型负载，单机单 worker async 本就够用；
  • 该套补丁目前仅 static-verified，未经真机 build + PG/Redis/k6 验证；
  • 红线：面 A turn 运行时在 WEB_CONCURRENCY>1 或多副本时必须先配 DEEPTUTOR_PG_DSN，否则跨 worker 的 turn 会被当孤儿杀掉。

当单机 8C16G 的 /api/metrics 出现持续 admission 饱和 / CPU 打满时，再按 docs/deeptutor-high-concurrency-rollout-runbook-20260602.html 走真机验证后启用——那是 1 万级 / 横向扩展的路线，不是 5000 日活的当务之急。

服务器侧后续（需在服务器操作，非本次代码）

  • 给容器加 mem_limit / cpus（避免 OOM 级联）——线上 override 已有部分，建议复核 qdrant/deeptutor 上限。
  • 对象存储分流 /api/outputs（仅 DeepTutor 可视化产物用，MathVerse 不消费，可缓议）。
