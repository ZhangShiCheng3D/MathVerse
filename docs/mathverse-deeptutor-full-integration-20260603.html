日期：2026-06-03 ｜ 范围：把 DeepTutor 引擎的全部能力系统性接入 MathVerse（面向 App），分 6 个阶段交付。

1. 背景：为什么做这次重构

重构前，MathVerse 严重欠用了 DeepTutor 这台强大的引擎，只调用了一个端点 /api/v1/chat，且存在三处根本问题：

  • 传给引擎的 mode 参数（solve/quiz/research/visualize）引擎根本不读（chat.py 只读 message/session_id/history/kb_name/enable_rag/enable_web_search/language）——所谓「5 种模式」是幻觉。
  • 「一个 flag 就能开」的 RAG（enable_rag+kb_name）与联网检索（enable_web_search）从未被设置。
  • DeepTutor 的智能体核心 /api/v1/ws（unified_ws turn runtime）完全没碰；拍照解题、判题等原生能力线上全部绕过（直连 DashScope / DeepSeek）。

  • turn.py — unified_ws turn runtime 客户端（TurnConnection）：start/subscribe/submit_reply/cancel/regenerate；按 metadata.turn_terminal 判终止。
  • rest.py — 按域分组的管理端点客户端（knowledge / notebook / vision-analyze …）。

  • 原 agent_client.py 保留并扩展（vision_solve / judge / explain_step / similar_question / visualize / RAG 参数），所有调用经 CircuitBreaker + admission 闸。

5. 多租户隔离（C2 —— 最关键的正确性设计）

DeepTutor 以 ENABLE_AUTH=false 运行，是单租户：sessions / 知识库 / 笔记本等都存在它自己的单一数据空间。MathVerse 是多用户的，因此采用两套隔离：

  • 命名隔离（MathVerse 控制名字的资源：kb_name、session_id）：一律加 mv_{uid}_ 前缀，uid 来自 JWT 而非用户输入，故仅靠前缀即可隔离。共享只读课程库为 mv_curriculum_{stage}。
  • 归属表隔离（DeepTutor 服务端生成 id 的资源：notebook/book…）：靠前缀无法隔离（id 非我方命名，且可被直接枚举访问）。改为在 MathVerse 侧建 DtResource（user↔domain↔dt_id）映射表，list 按归属过滤、所有按 id 的操作校验归属。该机制由 app/services/dt_ownership.py 提供，是所有服务端 id 域的通用方案。

已通过单测验证：用户 A 看不到 / 无法 get / delete 用户 B 的笔记本（引擎请求都不会发出）。

⚠️ 6'. 部署红线（C3 —— 务必遵守）

本次首次让 MathVerse 依赖 DeepTutor「面 A」（turn runtime，/api/v1/ws，由 /ws/tutor 使用）。

切勿在未设置 DEEPTUTOR_PG_DSN 的情况下把 DeepTutor 的 WEB_CONCURRENCY 提到 >1 或增加副本。否则 turn_runtime 会把跨 worker/副本的 turn 误判为 orphan 并杀掉（即 PR #2 的 P3a/P3b 修复项）。单 worker 下不受影响。

6. 暂缓项与理由（避免投机性代码）

以下能力未在本轮强行接入，因为会产生无法验证、依赖外部条件的投机代码（违背「简洁至上」）。它们都可沿用本轮已建好的模式（REST 透传 + DtResource 归属隔离）增量补齐：

  • KB-grounded 出题（question/generate、mimic）：默认依赖一个已填充语料的知识库，且事件结构不确定；当前「先搭管线、暂无语料」。现有 chat+JSON 出题（generate_quiz）已覆盖该功能，待真实教材语料灌入共享课程库后再切换。
  • AI 教材 (book) / 三层记忆 (memory) / 活动流 (dashboard)：与笔记本同属有状态域，可用 DtResource 模式补 BFF + 前端页；本轮优先交付与数学学习闭环最相关的笔记本。
  • 协作写作 (co_writer) / 导师 Bot (tutorbot souls)：对考试数学场景价值较低；tutorbot souls 属全局态，租户隔离需额外设计。建议按需再评估。
